Why does the metacal star shear-response R climb at the bright end? On 45,835 SKiLLS stars, ⟨R1⟩ rises from ~0 at the faint end toward ~2 for the brightest, with a large R1/R2 asymmetry (fabian-star-mag-range). Stars carry no shear, so in the ideal — deconvolve by the true PSF, shear the resulting point, reconvolve — the response is zero and the size unchanged, at any brightness (Fabian, 2026-06-22: "applying shear to a point should yield nothing but noise … no matter how bright the point"). The observed climb departs from that ideal, and the job is to understand what drives it: a code error, a PSF/noise systematic we can model and correct, or a genuine limitation of the metacal estimator near the point-source limit — a justified choice that simply has a failure mode here. This is a standard metacal validation step that other analyses largely control (DES reached ~0.05 and better; one that struggled traced it to bad PSFs), so it tends to finger PSF / coordinate / noise effects — but cosmic shear is hard and this diagnostic is unforgiving, so the task is to find the cause, not presume one, and to reduce R and size toward zero where the cause is fixable. Because it could live anywhere in the chain, the diagnosis runs through the full pipeline: observed on Fabian's SKiLLS sims, dissected on the controlled shapepipe-digital-twin twin (substrate and Fabian's inputs located — see Inputs / Substrate).

The physics, and what the data already says

  • Likely more than one cause — don't collapse to a single bug (Cail). The climb and the asymmetry need not share an origin; treat them as possibly-distinct, compounding systematics. A discriminator that demotes a candidate for one observable does not clear it for the other — the goal is to attribute each observable, not to crown one culprit.
  • The ideal null. With the true PSF: deconvolve a star → a point; shear a point → still a point; reconvolve → the round PSF. So R = d·e/d·g = 0 and the size is unchanged. The bright-end climb is a departure from this ideal — but the departure could be a code error, a modelable PSF/noise systematic, or an estimator limitation in the point-source regime; the discriminators below narrow which.
  • Bright-end localization ⇒ deterministic, not photon noise. The climb is worst where SNR is highest and photon noise least — which kills the correlated-noise hypothesis. But it rules out only stochastic noise: a wrong noise model (χ² below) is a deterministic systematic that survives the bright-end argument. → hunt a systematic.
  • R1 ≠ R2 ⇒ directional, not isotropic. A pure size / point-source effect gives R1 ≈ R2; the asymmetry points instead at a directional cause — a PSF shape/orientation error or a handedness/flip. Fabian's old offset bug gave R1 ≈ R2 (slack), so the offset does not supply the asymmetry: it is a new feature relative to that plot, fingering a PSF-shape/orientation error.
  • Size is co-equal with R. "Deconvolved point ⇒ ~zero size." We see size ≈ 0 while R is large; Fabian's old offset bug instead always gave a clearly larger, non-zero size (transcript). So the size≈0 + R1≠R2 pairing is doubly distinct from the offset signature and instead matches a PSF-shape error: a wrong PSF ellipticity (not size) deconvolves a star to ~a point carrying a directional residual.
  • χ²_red ≈ 0.1 ⇒ the noise model is overestimated (Fabian): residuals ~10× smaller than the assumed variance, so σ is inflated (~3×) or the weights too low. A measured anomaly, not a guess — it ties to the #749 PSF-prior / weight-map issue (no / under-scaled weight map → prior-dominated fits; reconcile-749-prior). Naively a noise overestimate biases the faint end more — opposite to what we see — so it is either a second effect or a subtler coupling; the deciding diagnostic is χ²_red vs magnitude.
  • nepoch=1 still breaks ⇒ inter-exposure offset isn't driving the climb (Fabian): with one epoch there is no offset to mis-propagate and the global (x0,y0) fit centers the model by design, yet R still climbs. This clears inter-exposure offset as the climb's driver — but not single-exposure coordinate handling, and not offset as a compounding contributor (hyp 3).

Hypotheses, ranked — each names what would confirm or refute it

  1. PSF-model mismatch — the PSF ShapePipe deconvolves by ≠ the PSF that rendered the sim image (Fabian's #1, and the leading explainer of the asymmetry+size≈0 combination). A star deconvolved by the wrong PSF isn't a point → residual ellipticity → non-zero R; brighter ⇒ worse (higher S/N reveals the deterministic residual — Fabian confirmed this magnitude dependence). Crucially a shape/orientation error supplies the directional R1≠R2 while leaving size ≈0 — exactly our signature — whereas a size error would inflate size (the offset/size signature we don't see). Fabian suspects the PSF passing/funneling specifically: "maybe Martin introduced a mistake when he refactored the code" — a flip/transpose in the hand-off is a pure orientation error. This is psf-model-error-not-absorbed pointed at stars — the twin already shows model-PSF size error → linear m, shape error → additive c, neither absorbed by R. Checks: (a) Fabian's concrete ask — residual plots between the PSF in his sim-render pickle dict (fake_psf_autom, built by psf_dict_script.py) and the PSF ShapePipe extracts via Martin's mapping module, "check these two agree"; (b) inject the measured shape/orientation mismatch on the twin via psf_model_shear and predict it reproduces R1≠R2 at ~zero size in isolation.
  2. Noise / weight-model mis-normalization — χ²_red ≈ 0.1 says the noise is overestimated. A direct measured anomaly, which is why it ranks high. Prime suspect: the weight map fed to ngmix — no / under-scaled weight → prior-dominated fits, the same #749 PSF-prior failure mode Axel's weight-map fix targets (reconcile-749-prior). A wrong noise model is deterministic, so it survives the bright-end argument that rules out photon noise. Check: χ²_red vs magnitude (does the overestimate deepen for bright stars — the test that decides whether this co-drives the climb?) and audit the weight map actually passed at the metacal / PSF-fit step. Honest tension: a naïve noise overestimate biases the faint end more, so this is either a second effect or a subtler coupling.
  3. Coordinate / WCS offset — live as a compounding cause of the climb, not of the asymmetry. The climb shape matches Fabian's old offset-bug plot closely (he wants his offset propagation double-checked), but that plot had R1 ≈ R2 and a clearly larger size — so offset explains neither our asymmetry nor our size≈0, and nepoch=1 shows inter-exposure offset isn't even driving the climb. It stays on the board because the climb could be compounded (Cail) and because Fabian's first ask is to verify coordinates propagate sanely. Checks: confirm coordinate propagation is reasonable; the *_bad_offset vs *_good_offset star tiles in /n09data/hervas/SP_simu_fab/ are the A/B — if R matches across them, inter-exposure offset is cleared as a contributor.
  4. Gauss vs FitGauss reconvolution kernel — a hint, not a cause. metacal_psf=gauss halves the ⟨R1⟩ break (metacal-psf-parameterized); Fabian saw the same. Read as evidence the internal ngmix PSF approximation is implicated (one kernel slightly broader than the other), not as the root cause.

Method — workflow-driven, because context hygiene is the point

The investigation runs through workflows, whose value is context management: every agent a workflow spawns gets a clean, walled context, so the survey of one hypothesis can't bleed into or rot another's. Inside a single workflow we compose the patterns the moment calls for — fan out the independent hypotheses in parallel; adversarially verify every candidate finding with a fresh-context skeptic (a result we want to believe must survive an independent challenge — the structural antidote to rationalizing the first answer); classify-and-act where the path branches on what's found; loop until the explanation is airtight, the deterministic loop (not a tiring context) holding the stop condition. We don't meta-organize a separate workflow per hypothesis — the workflow already supplies the walls; we compose fan-out / verify / loop within it.

Start by establishing a verified statistic set through the full pipeline — size & R vs mag (no cut), R1/R2 split, χ²_red vs mag, intermediate metacal stamps, PSF residuals — each statistic independently checked before it is trusted (the data comes back; don't lean on the first number).
